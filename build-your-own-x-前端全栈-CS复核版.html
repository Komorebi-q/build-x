Implementing Promises from Scratch（TDD）

主线

从状态机和 then 链开始，而不是背 API；适合作为整条路线的热身。

JavaScript4–8h中等异步 / 状态机
为什么做：异步错误传播、链式解析和微任务顺序直接影响前端与 Node 调试；它比再写一个业务页面更能暴露认知漏洞。
验收产出：实现 pending / fulfilled / rejected、thenable 解析、链式 then、catch，并为状态转换写自动化测试。
提高项：接入 promises-aplus-tests；用 queueMicrotask 对齐调度；补 finally、all、race、allSettled；记录与原生 Promise 的差异。
02

Build your own React

主线

用一个项目理解 JSX、Fiber 式工作单元、reconciliation、function component 与 hook。

JavaScript8–16h中等渲染器 / 调度
为什么做：你需要的是可迁移的渲染器心智模型，不是记 React 当前源码细节。教程是简化模型，不能等同于生产版 React。
验收产出：能渲染函数组件、分片执行工作、提交 DOM 更新，并让多个 useState 独立工作；用示意图讲清 render / commit。
提高项：实现 keyed reconciliation、批量更新、effect 清理与错误边界；设计能证明“节点复用正确”的测试，并比较一次全量重建与增量更新。

合并参照：Didact 源码。原文件的 Virtual DOM 教程不再单列；并非所有现代框架都依赖 Virtual DOM。

03

Build Your Own Module Bundler — Minipack

主线

从入口文件建立依赖图，再生成一个可运行 bundle，理解构建工具最小骨架。

JavaScript4–8h中等模块图 / Runtime
为什么做：以后排查重复依赖、循环引用、产物膨胀和插件顺序时，你看到的是图和转换流水线，而不只是一份 Vite / Webpack 配置。
验收产出：完成 parser → dependency graph → bundle runtime，能打印模块图，并用夹具测试嵌套依赖和重复依赖。
提高项：支持循环依赖与模块缓存；增加 source map、loader / plugin hook、增量重建；对比 ESM live binding 与 CommonJS value copy。
04

The Super Tiny Compiler

主线

用不到 200 行代码走通 tokenizer → parser → transformer → code generator。

JavaScript5–10h中等AST / 编译器
为什么做：Babel、ESLint、模板编译器和 codemod 都复用这些阶段；这是前端工具链回报最高的小型 CS 项目之一。
验收产出：为四个阶段分别写测试；给 AST 加 source location；遇到非法 token 时返回包含行列号的结构化错误。
提高项：任选 JSX 或 TypeScript 子集扩展语法；增加作用域与符号表、常量折叠、错误恢复、source map，并包装成可执行 CLI。

原文件的 Tiny Interpreter 与本项目概念重叠，放到完成编译器后的对照阅读，不再作为独立主线。

05

Browser Engineering

主线长项目

用 Python 从 HTTP 获取一路做到 DOM、样式、布局、绘制、事件与 JavaScript。

Python30–60h困难浏览器 / 渲染流水线
为什么做：这是整份仓库里对前端最有长期价值的项目。性能、布局、事件和安全边界会从分散知识变成一条可执行流水线。
验收产出：至少完成网络、HTML tree、CSS cascade、block / inline layout、paint 和基础交互；能追踪一个元素从字节到像素的全过程。
提高项：做一个 layout / paint inspector；输出阶段耗时；加入缓存、Cookie 和导航历史；为 same-origin 边界做威胁模型与负向测试。

安全补读：仓库中的 The Same-Origin Policy，但不要把它当成完整 Web 安全课程。

Build Your Own Web Server From Scratch in JavaScript

主线

绕开 Express，从 TCP 字节、HTTP 解析、路由和响应开始构造服务端。

Node.js12–20h中等TCP / HTTP
为什么做：这是从前端跨到后端最合理的第一步：浏览器中的 request / response 终于会落到 socket、字节边界和协议状态机上。
验收产出：实现最小 HTTP/1.1 parser、路由、静态文件与错误响应；用原始 socket 和自动化测试覆盖分段到达的请求。
提高项：支持 keep-alive、chunked body、流式响应和 backpressure；补超时、body 大小限制、路径穿越防护，再用负载测试记录吞吐与尾延迟。

Build a DNS Server in Node.js

选做

Node.js8–16h中等DNS / UDP
为什么做：域名故障、CDN、缓存 TTL 和服务发现都建立在 DNS 之上；这是比“背解析过程”更可靠的网络入门。

Build Your Own Redis with C/C++

主线长项目

C / C++25–45h困难网络 / 数据结构 / 缓存

仓库外仍然必须补：不要把 build-your-own-x 当完整全栈课程

“从零实现”擅长解释内部机制，但对生产约束、标准更新和运营流程覆盖不足。

认证与 Web 安全：原 SSO 文章是 2018 年的教学实现，且不包含 OAuth 流程；不能作为生产方案。另学 OIDC / OAuth、Session、Cookie、CSRF、XSS、密钥轮换与授权模型。
生产数据库：玩具数据库之后仍要学 PostgreSQL 的事务隔离、索引、执行计划、锁、迁移、备份与恢复。
测试体系：每个 build 至少要有 unit、integration、negative case；全栈项目再补 contract、E2E 和 load test。
部署与可观测性：补 CI/CD、配置与密钥管理、日志 / 指标 / trace、告警、回滚和容量规划；CDN 提高项可作为入口。
API 工程：补幂等、分页、限流、超时、重试、错误契约、版本策略与兼容性，而不是只会搭 CRUD 路由。
算法与数据结构：JavaScript Algorithms and Data Structures 适合作为随查资料与专项练习，不算一个可验收的 build。
