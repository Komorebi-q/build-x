React 渲染器机制速查

把 element、Fiber、分片工作、render / commit、reconciliation、函数组件与 Hook 槽位压缩到一页。它描述 P02 的教学模型，不声称等同于现代 React 内部实现。

Didact 教学模型React 官方概念对照适合打印

一、三个对象不要混用

Element

对目标 UI 的普通数据描述：type、props、children。它不是 DOM，也不保存工作进度。

Fiber

一次协调工作的节点记录：树指针、dom、alternate、effect 与 hooks。

DOM Node

浏览器宿主对象。只有 commit 阶段应改变已挂载 DOM。

Component

以 props 计算 element 的函数边界；函数组件 Fiber 可以没有 dom。

  • JSX 在运行前被转换为函数调用；renderer 处理的是调用结果。
  • 工作循环每次处理一个 Fiber，并保存 next unit。
  • 候选树完成后，commit 才把 effect 应用到宿主 DOM。

三、Fiber 字段地图

字段用途关键不变量
type / props描述本节点及其输入函数 type 与字符串 type 走不同路径
dom对应宿主节点或 root container函数组件通常为空
parent / child / sibling显式保存深度优先遍历关系每个非 root Fiber 恰有一个 parent
alternate连接上次已提交的同位置 Fiber用于读取旧 props、旧 dom、旧 hooks
effectTag记录 commit 要执行的宿主工作render 只标记，commit 执行
hooks按调用顺序保存函数组件状态每次 render 的顺序必须稳定

四、下一个工作单元

  1. 有 child：向下。
  2. 无 child、有 sibling：向右。
  3. 两者都无：沿 parent 向上，寻找第一个有 sibling 的祖先。
  4. 回到 root 仍没有：本轮候选树完成。

五、render 与 commit

RenderCommit
执行函数组件插入新宿主节点
创建候选 Fibers应用 property / event 差分
比较 old fiber 与 new element删除旧宿主子树
标记 effect，可在 unit 边界暂停本项目中连续完成，然后提升 current root
调试口诀

render 只回答“要做什么”；commit 才回答“现在对 DOM 做”。若暂停后页面出现半成品，副作用边界放错了。

六、简化 reconciliation 决策表

旧节点新描述结果
有同位置、同 type复用 dom，UPDATE
无有新建，PLACEMENT
有同位置、不同 type旧 DELETION + 新 PLACEMENT
有无DELETION

这是 index-based 教学策略，不解决 key、移动最优化与完整状态身份语义。

七、useState 槽位与队列

每次执行一个函数组件：
  currentHookIndex = 0
  newFiber.hooks = []

每次 useState：
  从 alternate.hooks[currentHookIndex] 找旧 hook
  以旧 state 为起点，按序折叠 pending actions
  保存 new hook
  currentHookIndex += 1

setter：
  向所属 hook queue 追加 action
  安排从 current root 开始的新一轮工作
  • Hook 身份 = 组件 Fiber 身份 + 稳定调用位置。
  • initial state 只在没有旧 hook 时提供起点。
  • 已消费 action 不能在下一轮重复应用。
  • 条件调用会使后续槽位错位，因此 hooks 必须在顶层稳定调用。

八、现象到不变量的排查表

现象优先检查
暂停时页面出现半棵树append / update 是否泄漏到 render
更新后节点全部换身份alternate 与 type 匹配是否正确
删除尾节点无效协调循环是否在 new elements 用尽后仍处理 old fiber
事件触发多次旧 handler 是否先移除
函数组件内容无法删除commit 是否跨无 dom Fiber 查找宿主节点
第二个 state 被第一个覆盖hookIndex 重置、递增与 old hook 查找
连续更新少执行一次action queue 是否基于前一计算结果顺序折叠
