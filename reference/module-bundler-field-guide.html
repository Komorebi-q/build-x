模块打包器机制速查

把 asset、specifier resolution、依赖图、module table 与 bundle runtime 压缩到一页。它描述 P03 的教学模型，不代表完整 ESM 或生产打包器。

Minipack 教学骨架ESM / Babel 边界适合打印

一、六个对象不要混用

Raw specifier

源码 import 中的字符串，例如 ./util.js；只有结合 importer 才能解析。

Canonical filename

resolver 产出的规范文件身份；用于图去重和错误语境。

Module id

bundle 内索引模块记录的稳定键；不是源路径本身的语义替代。

Asset

一个源模块的构建期记录：身份、依赖列表、转换代码和局部 mapping。

Module graph

从入口可达的有向图；节点是资产，边是 importer 中声明的依赖。

Module instance

运行期的 module/exports 状态；图节点唯一不自动保证实例只执行一次。

四、最小解析契约

resolve(importerFilename, rawSpecifier) → canonicalFilename

核心课建议显式声明：
  接受：./ 或 ../ 开头的 JavaScript 文件
  基准：importer 所在目录
  规范化：. 与 ..；是否解析 symlink 必须说明
  失败：带 importer、raw specifier、候选路径的结构化错误
  不包含：bare packages、alias、package exports、URL、动态 import
Host-defined 边界

ECMAScript 不规定所有环境如何把 specifier 映射到具体文件。课程规则只是你打包器的公开契约，不是 Node、浏览器或 Webpack 兼容声明。

五、图构建与菱形不变量

  1. 规范化入口，创建资产并立刻登记 canonical filename → asset。
  2. 从工作表取一个 asset，逐个解析它的 raw specifier。
  3. child identity 未登记时才创建资产并加入工作表。
  4. 无论 child 是否新建，都在父 asset.mapping 写 raw specifier → child id。
  5. 工作表为空时，返回可达资产和 entry id。

六、Module table 形状

moduleTable:
  moduleId → [moduleWrapper, localMapping]

moduleWrapper(localRequire, module, exports):
  执行该资产的 transformed code

localMapping:
  当前父模块中的 raw specifier → child moduleId
  • wrapper 保留模块顶层作用域边界。
  • mapping 是数据，使用可靠序列化；不能做成全局 specifier 表。
  • 整份产物应通过 parser 语法检查，并对同一输入保持确定。

七、Runtime 加载轨迹

require(parent id)
→
parent wrapper
→
localRequire(raw)
→
parent mapping
→
require(child id)
  • 初始 exports 形参与 module.exports 指向同一个对象。
  • 重新给局部 exports 赋值不会自动替换 module.exports。
  • 缺 mapping 时错误应带 parent id 与 raw specifier；缺记录时带 child id。
  • build trace、runtime trace 与 application output 分开记录。

八、可选模块缓存状态

状态动作再次请求
absent创建实例，并在执行 wrapper 前登记进入 loading
loading可能处于循环返回部分 exports 或按策略报错
loadedwrapper 已完成返回同一 module.exports
failed（可选）wrapper 曾抛错明确重抛、删除或重试策略

这种缓存能建立 CommonJS 风格模块实例身份，但不自动实现原生 ESM 的实例化、TDZ、live bindings 或循环语义。

十、教学模型边界

  • Babel CommonJS transform 只改写语法，不替打包器解决 resolution。
  • 对象式 exports runtime 不等同于原生 ESM Module Records 与 live binding。
  • 核心单文件 bundle 不包含 tree shaking、chunk graph、动态加载和生产优化。
  • source map 需要组合每次转换的位置映射，不能靠追加文件名代替。
  • loader/transform hook 与 lifecycle plugin 应有明确阶段、顺序、错误和可变性契约。
  • 增量重建需要缓存、反向依赖和失效传播，并以全量构建结果为对照。
