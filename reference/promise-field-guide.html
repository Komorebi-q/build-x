Promise 机制速查

把状态、reaction、链式传播、resolution procedure 和调度边界压缩到一页。遇到实现分支时先查这里，再回规范定位条款。

Promises/A+ ECMAScript Promise Jobs 适合打印

一、先统一词汇

promise

拥有符合规范行为的 then 方法的对象或函数。

thenable

只要定义了可调用的 then，就可能被吸收；它不一定是本实现创建的 Promise。

pending

尚未锁定最终结果，可以转向 fulfilled 或 rejected。

fulfilled

拥有一个不再变化的 fulfillment value。

rejected

拥有一个不再变化的 rejection reason；reason 可以是任意 JavaScript 值。

settled

fulfilled 或 rejected 的统称；settled 后不能再切换状态。

resolved

结果已被“锁定”。它可能已 settled，也可能正在跟随一个仍 pending 的 thenable。

reaction

处理 fulfillment 或 rejection 的记录，通常还携带派生 Promise 的能力。

最常见的术语错误

resolved 不等于 fulfilled。当 Promise resolve 到另一个 pending Promise 时，它已不能被第二次 resolve，但仍可能保持 pending。

二、状态机只允许单向迁移

PENDING初始状态
→
FULFILLEDvalue 固定
或
REJECTEDreason 固定
  • 第一次有效的 resolve / reject 决定结果，之后的调用必须忽略。
  • executor 在构造期间同步调用；reaction handler 不在当前调用栈内调用。
  • “值不变”指身份不再变化，不代表对象被深度冻结。

三、then 的四条传播规律

父 Promise 结果 选中的 handler handler 行为 派生 Promise
fulfilled onFulfilled 返回普通值 x 通过 [[Resolve]](child, x) 决定
rejected onRejected 返回普通值 x 通常转为 fulfilled；这是错误恢复
任一状态 对应 handler 抛出 e 以 e rejected
任一状态 handler 缺失 不执行用户函数 原 value / reason 透明传递

then 每次都返回一个新的 Promise。不要把 handler 的返回值直接塞进 child；必须先进入 resolution procedure。

四、Promise Resolution Procedure

输入是派生 Promise child 与 handler 返回值 x。实现时按顺序做决定，不能随意交换步骤。

  1. child === x？是则以 TypeError 拒绝，阻止直接自解析。
  2. x 不是对象也不是函数？直接以 x fulfilled。
  3. 读取一次 x.then。getter 若抛错，以该错误 rejected；不要重复读取。
  4. then 不可调用？把整个 x 当普通值 fulfilled。
  5. 以 x 为 this 调用 then。传入递归 resolve 与 reject，并用 once guard 保证第一次调用获胜。
  6. 调用 then 时抛错？若回调尚未被调用则 reject；否则忽略这个迟到的异常。
危险捷径

只用 instanceof 判断 Promise 会漏掉跨实现、跨 realm 和手写 thenable；多次读取 x.then 也会被有副作用的 getter 破坏。

五、调度边界

当前 JS 调用栈
→
Promise reaction job
→
下一个 task
  • Promises/A+ 只要求 handler 在当前栈结束后执行，允许宏任务或微任务方案。
  • 现代原生 ECMAScript Promise 会为 reaction 创建 Job，并交给 host 排队。
  • 教学实现若要贴近浏览器与 Node 的原生顺序，可把 queueMicrotask 包在可替换的 scheduler 边界后。
  • 微任务会持续排空；递归制造微任务可能饿死计时器和渲染。
