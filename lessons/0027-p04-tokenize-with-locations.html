P04 · Lexical Analysis

让每个 token 都能指回源文本

你将用单向游标识别括号、数字、字符串和名字，同时维护 offset、line、column。正确 token 不只携带 value，还要成为后续 AST 与错误诊断的位置证据。

60–90 分钟方法：测试驱动产出：tokenizer、位置测试、词法错误

本节目标

维护统一游标

每消费一个字符，offset、line、column 同步推进。

保存半开区间

token span 使用 start-inclusive、end-exclusive，能够直接切片回源。

识别最长词素

连续数字或字母只产生一个 token。

词法失败可定位

未知字符和未闭合字符串返回稳定错误码与位置。

先固定位置约定

字段约定用途
offset从 0 开始的源码索引直接切片、排序和计算 span
line从 1 开始符合编辑器与 ESTree 常见展示
column从 0 开始符合 ESTree Position
loc.end被消费片段后的第一个位置slice(start, end) 无需加一
换行不只是 whitespace

它虽然不形成 token，却会把 line 加一并把 column 归零。先约定核心课只处理 \n，还是也规范化 \r\n；测试必须反映你的选择。

任务拆解：从 RED 开始

1

为 token 形状写表驱动测试

  1. 单字符：(、)。
  2. 连续词素：123、subtract。
  3. 混合输入：空格、tab 和跨行嵌套调用。
  4. 字符串：空字符串、含空格字符串、跨行是否允许。
  5. 对每个 token 同时断言 type、value、start、end，并验证源码切片。

检查点：先看到测试因为“没有位置字段”而失败，而不是因为测试本身无法运行。

2

只实现一个推进原语

把“读取当前字符”和“消费一个字符后更新三个坐标”分开。所有 token 分支都必须走同一个推进原语，避免数字、字符串、空白各自复制换行逻辑。

位置 := { offset, line, column }
consume():
  读取当前字符
  offset 前进
  若字符是换行：line 前进，column 归零
  否则：column 前进
  返回字符

检查点：跨行 token 后的下一个 token 起点正确。

3

最后补负向路径

  1. 未知字符：例如核心文法外的 @。
  2. 到达 EOF 仍未找到结束引号。
  3. 错误至少包含 phase=tokenize、稳定 code、message、start/end 和 sourceName。
  4. 断言字段，不对完整人类文案做脆弱快照。

交付：正例矩阵、两个负向测试及一张游标状态表。

逐级提示

提示 1：怎样捕获 token 的 start？

进入某个 token 分支时先复制当前位置；消费完整词素后再复制 end。不要让 start 指向可变游标对象。

提示 2：怎样避免 EOF 上的正则陷阱？

循环条件先明确检查游标是否仍小于输入长度，再测试当前字符；不要让 undefined 悄悄进入字符串 value。

提示 3：怎样表示错误？

考虑一个共享诊断记录或自定义错误类型；测试关心结构字段，CLI/界面再负责渲染带插入符的文本。

自查问题

  1. 为什么不能只在产生 token 时更新行列？
  2. 空白没有 token，为什么仍必须消费并更新位置？
  3. 123abc 在你的文法里是两个 token、一个非法词素，还是别的结果？契约是否明确？
  4. 字符串 token 的 span 包含引号吗？value 包含引号吗？为什么可以不同？
  5. 你能用任一 token 的 offset span 精确切回原始 lexeme 吗？
