P02 · Fiber Traversal

让每一步工作都有暂停点

递归渲染会一路占住调用栈。你将把树转换拆成一个个可恢复的工作单元，并用 child / sibling / parent 指针完成无递归深度优先遍历。

60–90 分钟难度：中等产出：Fiber 遍历器与访问序列测试

问题不是“递归慢”，而是缺少控制权

递归函数在返回前由 JavaScript 调用栈保存进度。若一次处理整棵大树，外层调度器无法在节点之间检查预算。Fiber 教学模型把恢复信息放进显式对象，让循环每完成一个节点就能交还控制权。

element

声明目标 UI，通常短命且可重新创建。

fiber

保存一次渲染工作的节点、连接关系和未来副作用。

unit of work

处理一个 Fiber，并返回下一个要处理的 Fiber。

work-in-progress root

尚未提交的整棵候选树。

1

把一棵 element tree 手工改画成 Fiber 链

使用至少三层、两个兄弟节点的树。标出 root 的 child、每个节点的 sibling 和 parent；然后闭卷写出访问顺序。

交付：element 树、Fiber 指针图和预期访问序列。

下一个工作单元的选择规则

  1. 当前节点有 child：下一个是 child。
  2. 没有 child 但有 sibling：下一个是 sibling。
  3. 两者都没有：沿 parent 向上，直到找到拥有 sibling 的祖先。
  4. 回到 root 仍找不到：遍历完成。

这是“先序深度优先”的显式版本。每次函数调用只处理一个节点，并把恢复点作为返回值交给循环。

2

先实现纯遍历，不创建 DOM

用手工构造的 Fiber 对象收集访问 type。覆盖单节点、直链、多个兄弟、从深层回溯到叔叔节点四种结构。

交付：四个纯数据遍历测试；DOM 测试暂时为零。

一个工作单元只承担两件事

处理当前 Fiber
→
建立 child / sibling
→
返回 next Fiber

“处理当前 Fiber”在宿主节点路径上可以准备 DOM、读取 children；但现在不要挂载 DOM。你正在构建候选树，不是在向用户展示半成品。

提示 1：兄弟节点如何连接

遍历 children 数组时，第一项成为 parent.child；后续项连接到前一个 child fiber 的 sibling。

提示 2：为什么每个 child 都要有 parent

叶子没有 child 或 sibling 时，只有 parent 链能帮助它找到祖先的 sibling。

提示 3：如何防止职责膨胀

为“创建 child fibers”和“选择下一个 Fiber”分别写测试。若一个测试必须同时查看 DOM 与访问顺序，边界可能混在一起了。

闭卷说出四条不变量

  • 除 root 外，每个 Fiber 恰有一个 parent。
  • 同一 parent 的 children 通过 sibling 链保持原顺序。
  • 一次工作单元不会递归处理后代。
  • 访问完成后，所有可达 Fiber 恰好被处理一次。
