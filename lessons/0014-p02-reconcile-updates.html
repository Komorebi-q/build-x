P02 · Reconciliation

比较旧树与新描述，只提交必要变更

把已提交 Fiber 作为 alternate 与新 element 逐位置比较，为新树标记 placement、update、deletion；然后让 commit 阶段消费这些标记。

90–120 分钟难度：中高产出：三类 effect 与节点复用证据

先定义这个教学 diff 的身份规则

本课先采用同一父节点下、同一位置、同一 type视为可复用。它故意不解决 keyed reorder；只有先把简化规则写明，才能判断每个结果是 bug 还是范围限制。

手工推演四组 sibling 列表

分别覆盖只改文本、末尾新增、末尾删除、同位置换 type。为每个位置写 old/new/effect，并预测 DOM 身份是否保留。

交付：四张逐位置 diff 表。

alternate 连接“上次已提交”与“本次候选”

current fiber
↔
new fiber.alternate
→
effectTag

不要原地修改 current tree 来充当候选树。current 要继续解释当前 DOM；new fiber 通过 alternate 读取旧 props 与旧 DOM，直到新树完成并提交。

删除项无法留在新 child 链中，因此需要单独的 deletion 集合，等待 commit 时处理。

DOM 更新要做差分，而不是只覆盖新值

  1. 移除旧而新没有的事件监听器。
  2. 移除旧而新没有的普通 property。
  3. 添加或替换发生变化的普通 property。
  4. 添加新事件监听器。

顺序不是唯一可行答案，但必须确保旧 handler 不残留、被删除的 property 真正消失。用调用次数和 DOM 当前值验证，不只看视觉结果。

2

为 property diff 建立纯函数矩阵

输入 old props 与 new props，输出待 remove / set 的 property 与 event 集合。至少覆盖新增、变化、删除、未变化四类。

交付：属性差分矩阵、事件替换测试和一次 DOM 集成测试。

让 commit 成为 effect 的唯一执行者

PLACEMENT

把新宿主节点接到最近的宿主 parent。

UPDATE

复用已有 dom，应用旧 / 新 props 差分。

DELETION

从宿主 parent 移除旧子树对应的 DOM。

NO EFFECT

结构和 props 均无需宿主变化，仍可遍历后代。

3

用节点身份和操作计数证明增量更新

保存更新前 DOM 节点引用；修改一个文本和一个 property 后，断言可复用节点身份不变，同时记录没有发生全容器清空。

交付：placement/update/deletion 集成测试与复用证明。

用反例写清 index diff 的边界

在列表头部插入一项，再交换两项顺序。观察无 key 的逐位置比较产生多少 update，以及局部状态未来可能跟错哪个位置。此时先记录问题，不在本课实现 keyed reconciliation。

范围说明

“DOM 最终看起来对”不代表协调策略高效或状态身份正确。keyed reconciliation 是 P02 通过核心验收后的扩展项。

逐级提示

提示 1：删除最后一个 child 没反应

循环条件不能只依赖 new elements；只要 old fiber 仍存在，就还有删除工作要生成。

提示 2：更新后事件触发两次

确认旧 handler 在新 handler 注册前被移除，并且比较的是 alternate.props 与新 props。

提示 3：第二次更新失去旧树

commit 完成时，新 root 需要成为 current；下一次 render 的 root.alternate 再指向它。
