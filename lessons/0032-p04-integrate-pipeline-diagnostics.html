P04 · Integration & Diagnostics

让端到端编译保留每个阶段的责任

最后的 compiler 函数应该只是流水线编排。你会用中间产物快照、阶段 trace 和统一诊断 schema 证明：组合没有抹掉单阶段的可测试性与错误位置。

60–90 分钟核心：集成测试 + 结构化错误产出：错误契约、阶段矩阵、端到端证据

本节目标

薄编排器

compiler 只按顺序连接阶段，不复制阶段逻辑。

统一诊断

词法、语法与内部错误共享字段，保留不同 code。

分层测试

单元、阶段连接、端到端与负向案例各自回答不同问题。

诚实边界

明确这是极小语言编译器，不是 JavaScript/Babel 替代品。

定义诊断记录，而不只是异常文案

Diagnostic:
  phase: "tokenize" | "parse" | "transform" | "generate"
  code: 稳定、适合测试的机器标识
  message: 面向人的简洁说明
  sourceName: 输入来源
  loc: { start, end }
  details?: 额外上下文，例如 found / expected / nodeType

Babel Parser 区分粗粒度 code 与细粒度 reasonCode，并把可选错误恢复得到的错误放在 AST 上。P04 核心不实现恢复，但可以借鉴“稳定分类字段与人类文案分离”的原则。

不要伪装恢复

核心实现采用 fail-fast：返回或抛出一个结构化诊断并停止当前编译。能收集多个错误需要同步点与恢复策略，属于提高项，不是 catch 后继续循环。

测试矩阵：证明阶段，也证明连接

层级输入到输出主要证据
单元source→tokens；tokens→source AST；source→target AST；target AST→code每个失败定位到单阶段
连接tokens→target AST；source AST→code相邻 schema 对得上
端到端source→code多顶层、嵌套、字符串与确定输出
负向非法 source / AST→Diagnosticphase、code、loc、sourceName 正确
语法验证generated code→目标 parser产物是合法 JavaScript

任务拆解

1

连接薄流水线

让编排代码按固定顺序传递输出；给每个阶段增加可选 trace hook 或在测试中直接调用阶段函数。回答：若未来增加 optimize，它插在何处，输入输出 schema 是什么？

检查点：compiler 自身没有字符分类、AST switch 或打印标点。

2

建立端到端夹具集

  1. 空输入。
  2. 单个与多个顶层调用。
  3. 至少三层嵌套。
  4. 数字与字符串混合。
  5. 跨行输入，最终行为与单行等价但诊断位置不同。
  6. 未知字符、未闭合字符串、缺 name、多余右括号、未闭合 call。

检查点：负向案例断言结构字段，不仅使用 toThrow()。

3

记录一次失败假设

选择一个真实 bug：例如 EOF 读取崩溃、嵌套 loc 结束位置错误、源 AST 被污染或字符串生成无效。记录现象、最初假设、最小复现、观测证据、修正假设与回归测试。

交付：测试矩阵、阶段 trace、诊断样例和排查记录。

把诊断对象渲染成人能读的提示

example.tiny:2:5 [parse/EXPECTED_CALL_NAME]
  调用左括号后需要函数名，但看到了 number
  ( 123 4)
    ^^^

渲染器是诊断数据的消费者。错误对象保存事实，渲染器负责文件名、行文本、插入符与中文文案。这样测试、CLI 和编辑器未来可以共享同一诊断。

逐级提示

提示 1：怎样测试错误位置而不绑定完整 message？

断言 phase、code、sourceName、start/end 与 details；message 只断言关键语义或单独测试 formatter。

提示 2：trace 应记录什么？

记录阶段名、输入摘要与输出摘要，不打印完整巨大 AST。核心夹具可保存 token 数、根节点类型、body 数和输出长度/文本。

提示 3：如何避免端到端测试重复单元测试？

端到端只选代表性路径和阶段连接；所有字符类别、节点类型和错误细分仍由单元测试承担。

自查问题

  1. 为什么 toThrow() 不能证明错误质量？
  2. phase 与 code 分开有什么价值？
  3. 一个 parser 错误的 loc 应来自当前 token、上一个 token还是调用起点？如何按错误种类选择？
  4. 为什么有 loc 还不等于有 source map？
  5. 若 tokenizer 的 token schema 改变，哪些连接测试会最先报警？
