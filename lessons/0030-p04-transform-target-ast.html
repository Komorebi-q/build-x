P04 · Transformation

把“同一含义”重新编码为目标树

转换不是改几个字段名。你会明确源 schema 与目标 schema 的映射、顶层表达式为什么要包装成 statement，并让每个目标节点保留来源位置。

60–90 分钟核心：source AST → target AST产出：映射表、转换测试、位置传播规则

本节目标

区分两套 schema

源 Call 的 name/params 与目标 Call 的 callee/arguments 含义相关但形状不同。

构造新树

不让目标字段泄漏进源 AST 的公共 schema。

处理上下文

同一个 call 在顶层需要 statement 包装，在参数中仍是 expression。

传播 provenance

新节点能追溯到对应源节点的 location。

任务拆解

1

测试 leaf 与 context

  1. 单个 number/string 节点转换后值与 loc 不丢失。
  2. 嵌套 call 的 callee 是 Identifier，参数顺序不变。
  3. 顶层 call 有 ExpressionStatement；参数中的 call 没有多余 wrapper。
  4. 多个顶层表达式各自形成目标 Program.body 项。
  5. 源 AST 在转换后不出现目标专用字段或临时可枚举属性。

检查点：分别断言源树未被污染和目标树形状正确。

2

选择一种上下文策略并写下取舍

上游参考会在源节点上挂临时 _context，把旧树与新树的目标数组连接起来。你可以学习这个机制，也可以使用显式递归返回值或独立 context map。无论选择哪种，都回答：

  • 目标孩子由谁追加到哪个数组？
  • 顶层与嵌套 call 如何区分？
  • 重复运行 transformer 是否得到相同结果？
  • 源 AST 是否仍符合它原本的公开 schema？

交付：一页策略说明和对应不变量测试。

3

定义位置传播

  1. 目标 literal 与 call 继承对应源节点 loc。
  2. callee Identifier 至少指向源 call 名称的 span；若源 AST 没保存 nameLoc，先决定是否补字段。
  3. 生成的 ExpressionStatement 可继承整个顶层 expression span，并标明它是 synthetic wrapper。
  4. 不要编造不存在于源文本中的精确字符位置；synthetic 节点要有明确策略。

交付：目标 AST 中每类节点的 provenance 规则。

逐级提示

提示 1：顶层 literal 也要 statement wrapper 吗？

先看目标语言 Program.body 的契约。若 body 只接收 statement，那么任何顶层 expression 都应统一包装，而不是只特判 call。

提示 2：怎样证明参数顺序没变？

使用不同值和不同嵌套形状的三个参数，断言目标 arguments 的结构序列；不要只用三个相同数字。

提示 3：怎样避免源树污染？

转换前后序列化或深冻结源 AST，或检查不存在额外字段。选择与你当前工具相匹配的证据。

自查问题

  1. 为什么 parser 不直接生成目标 AST？分离后你获得了什么可测试边界？
  2. Identifier 的位置与整个 CallExpression 的位置为什么不同？
  3. synthetic node 没有原文字符时，loc、origin 或 generated 标记怎样表达更诚实？
  4. 转换前后哪些语义必须保持，哪些表面形状必须改变？
  5. 如果以后做常量折叠，应该放 parser、transformer 还是 generator？为什么？
