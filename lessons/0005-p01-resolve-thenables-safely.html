P01 · Resolution Procedure

把不可信 thenable 安全地吸收进来

handler 可以返回任何值，包括来自另一套实现的 thenable。你需要一个防御性决策程序：只读一次 then、只接受第一次回调、递归解析并阻止自引用。

60–80 分钟 难度：困难 产出：对抗性 thenable 测试

先纠正一个关键等式

fulfill(value)

把普通最终值写入 Promise，并进入 fulfilled 终态。

resolve(x)

运行解析程序；可能立即 fulfill，也可能跟随另一个仍 pending 的 thenable。

resolved 可能仍 pending

若外部 resolve 收到一个 pending thenable，当前 Promise 的结果已被锁定，后续 reject 必须忽略；但它要等 thenable 决定后才会 fulfilled 或 rejected。这正是“只看 state 是否 pending”不够的场景。

把规范翻译成六个决策

输入为目标 Promise promise 与候选结果 x。按顺序执行：

  1. promise === x？以 TypeError reject，阻止直接自解析。
  2. x 是普通原始值？直接 fulfill；null 也走这里。
  3. 读取一次 x.then。读取动作本身可能触发 getter 并抛错；此时 reject。
  4. then 不可调用？把整个对象 x 当普通值 fulfill。
  5. 调用保存下来的 then。令 this 为 x，传入递归 resolve 与 reject，并共享一次性闩锁。
  6. 调用抛错？若回调从未赢得闩锁则 reject；若已有回调获胜则忽略迟到异常。

这不是“判断是否为自家 Promise”的类型分支，而是一个跨实现互操作协议。

先写七个对抗测试

测试必须自己构造 thenable，不要只使用原生 Promise；否则很多 getter 与多次回调分支永远到不了。

交付：七个先红后绿的对抗测试，以及每个测试对应的 Promises/A+ 条款号。

用伪代码核对控制流

resolvePromise(promise, x)
  如果 promise 与 x 是同一对象：reject TypeError
  如果 x 不是对象或函数：fulfill x

  尝试读取且只读取一次 x.then
    读取失败：reject 该异常

  如果 then 不可调用：fulfill x

  创建本次 then 调用共享的 called 闩锁
  尝试以 x 为 this 调用 then
    resolvePromise(y)：若首次调用，递归 resolvePromise(promise, y)
    rejectPromise(r)：若首次调用，reject promise with r
  若调用 then 抛错且尚无回调获胜：reject 该异常

这里有两层“一次性”：构造器交给 executor 的 resolve / reject 共享一个锁；每次调用外部 thenable 的两个回调也共享自己的锁。它们保护的边界不同。

3

把临时 resolve 替换为解析程序

  1. 先通过普通原始值与普通对象测试。
  2. 加入 getter 异常和非函数 then。
  3. 加入单层、嵌套 thenable。
  4. 最后处理多次回调、迟到异常和直接自解析。
  5. 回归前四课全部测试，确认普通传播没有破坏。

交付：完整解析程序测试组；列出此次重构影响的旧测试。

手工追踪最刁钻的路径

假设 handler 返回 thenable A；A 调用 resolve(B)；B 的 then getter 抛出错误 E。闭卷回答：

  1. child 在哪个时刻被锁定？
  2. 需要读取几次 A.then、几次 B.then？
  3. 最终 child 的状态与 reason 是什么？
  4. 如果 A 在 resolve(B) 后又 reject(R)，R 是否生效？
核对时间线

A 的 resolve 回调第一次获胜后，解析递归进入 B；A 的后续 reject 被忽略。A.then 与 B.then 各读取一次。读取 B.then 抛出 E，因此 child 最终 rejected(E)。

四条不能走的捷径

  • 只用 instanceof：会漏掉跨实现、跨 realm 与手写 thenable。
  • 重复读取 x.then：getter 可能每次返回不同值或产生副作用。
  • 使用固定递归深度：A+ 不允许把“很深”随意等同于“循环”；只要求直接自解析必须拒绝。
  • 把 then 的返回值当结果：协议看的是它调用哪个回调，而不是 then 方法自身 return 什么。
