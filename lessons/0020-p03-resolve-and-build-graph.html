P03 · Resolution & Graph

让每条 import 边找到唯一文件身份

单个 asset 只知道源码里的 specifier。现在你要加入 importer 语境、定义最小解析规则，并用工作队列建立一个可打印、可去重、可失败的有向图。

55–80 分钟核心：resolve 与 graph identity产出：菱形图与建图测试

先理解：边的标签不是节点身份

两个不同目录都可以写 ./util.js，却指向不同文件；同一个文件也可能被 ./shared.js 与 ./dir/../shared.js 指向。解析必须同时接收 importer 与 specifier，再产出规范文件身份。

resolve(importerFilename, rawSpecifier) → canonicalFilename

本课程核心规则示例：
  只接受以 ./ 或 ../ 开头的 JavaScript 文件 specifier
  相对 importer 所在目录解析
  规范化 . 与 ..
  文件不存在或越出声明范围时给结构化错误
解析规则是宿主/工具策略，不是 parser 猜出来的

ECMAScript 规范把 module specifier 的实际加载与规范化留给 host。浏览器、Node 和打包器可以有不同规则。P03 必须把自己的极小规则写进 README 和测试，不能暗示已兼容 Node 或 Webpack resolution。

亲自完成：使用工作队列展开可达图

队列或栈都能找到可达模块。选择会改变发现顺序，但不应改变边关系和最终业务语义。下面只给数据流，不给 JavaScript 实现：

以入口的 canonical filename 创建第一个资产
立刻把“文件身份 → 资产”登记到索引
把入口放入待处理工作表

  对它的每个 raw specifier：
    结合 importer 解析 child canonical filename
    若文件身份尚未登记：创建、登记并加入工作表
    在当前资产的局部 mapping 记录 raw specifier → child id

建立四组文件夹具

  1. 单节点：入口无依赖；图有一个节点、零条边。
  2. 链：entry → message → name；边方向与每个 importer 的 mapping 正确。
  3. 菱形：entry → left/right → shared；四个唯一节点、四条边，shared id 相同。
  4. 失败：引用不存在文件；错误包含 importer、raw specifier 和解析后的候选路径。

交付：图的规范化快照或结构断言、失败错误样例，以及精确运行命令。

建议把“打印图”做成数据序列化边界

输出每个节点的 id、相对项目根的 filename 和边列表；测试数据结构，不要把 ANSI 颜色或终端排版当核心逻辑。绝对机器路径会让快照不可移植。

即使暂不支持循环，也不能无限展开

若 A → B → A，先登记后展开的身份索引会阻止重复建节点。核心阶段可以明确选择：

  • 图允许形成回边，但 runtime 语义标为未支持；或
  • 建图检测到回边后抛出结构化“循环暂不支持”错误。

两种选择都必须有终止测试。悄悄无限循环、重复读文件直到内存耗尽，不能算“尚未实现扩展”。

提示 1：如何区分回边与普通共享边

只用“见过该文件”能去重，却不能区分它仍在当前展开链上还是早已完成。需要时记录 unseen / visiting / done 或维护当前祖先链。

提示 2：id 何时分配

同一 canonical filename 第一次被发现时分配一次，并与资产一起登记；之后所有边复用该 id。
