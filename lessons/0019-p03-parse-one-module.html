静态 import 不等于所有模块依赖语法

P03 核心只要求你声明并测试的静态 import 子集。重导出、动态 import()、CommonJS require 和非 JavaScript 资源都要么实现并测试，要么清楚报“不支持”，不能悄悄漏边。

先写测试，再写资产函数

  1. 无 import：依赖数组为空，业务表达式仍保留在转换结果中。
  2. 默认、命名和副作用 import：按源码顺序提取三个 specifier。
  3. 字符串与注释内的伪 import：不得产生依赖。
  4. 非法语法：返回或抛出你定义的结构化错误，至少保留文件名与位置。
  5. 同一源码重复分析：除分配 id 的策略外，输出应可比较且稳定。

交付：asset 数据形状、五组测试名称、红绿测试摘要；实现由你亲自完成。

转换层的真实职责

Minipack 使用 Babel 把 ESM 语法转成调用 require(specifier) 并写入 exports 的代码。Babel 官方明确说明：CommonJS transform 只转换 import/export 语法，并不知道不同环境的模块解析算法。因此：

  • “发现依赖”来自 AST 遍历；“把 ESM 变成 runtime 能执行的代码”来自 transform。
  • “specifier 对应哪个模块 id”仍由你的 graph/resolver 决定。
  • transform 成功不表示你完整实现了原生 ESM 的链接、live binding、循环求值或异步模块。
3

对照转换前后建立契约

选一个默认 import + 命名 export 的隔离示例，只圈出 import 如何变成加载调用、export 如何进入导出对象。写下 runtime 必须注入的形参和对象，不需要解释 Babel 的全部 helper。

交付：一张“ESM 语法 → runtime 期待”对照表。

逐级提示

提示 1：parser 选项

确认 parser 按 module 而不是 script 解析；同时记录源码文件名，以便错误和后续 source map 能指回来源。

提示 2：访问哪个节点

AST visitor 应针对依赖声明的节点类型读取其 source.value，不要遍历所有 StringLiteral 后猜用途。

提示 3：错误位置

现代 Babel parser 默认可提供节点与语法错误的行列信息。把文件名与 parser 原始位置包进你自己的错误契约。

提示 4：测试难写时

若测试必须创建大量临时文件才能检查 AST 提取，说明读取与分析两个职责可能还黏在一起。
