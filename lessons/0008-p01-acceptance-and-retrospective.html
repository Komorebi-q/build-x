先补齐核心范围：catch

catch(onRejected) 的核心语义可以由 then(undefined, onRejected) 表达。重点不在多写一个分支，而是确保它复用同一条 child 传播与解析路径。

1

用三个测试逼出 catch

  1. rejection reason 被传给 handler。
  2. handler 返回普通值时，catch 返回的 child fulfilled。
  3. handler 抛错或返回 thenable 时，沿已有解析规则传播。

交付：一个薄 catch API 与三个证明它没有复制传播逻辑的测试。

关卡三：十分钟闭卷讲解

不看代码、不看速查页，按顺序回答：

  1. Promise 保存了哪些状态与队列？每部分负责什么？
  2. resolve 到 pending thenable 时，为什么“已锁定但仍 pending”？
  3. 为什么 then 必须返回 child，而不是 parent？
  4. 失败 handler 返回普通值后，为什么链条恢复为 fulfilled？
  5. 读取 x.then 时为什么必须只读一次并捕获异常？
  6. Promises/A+ 全绿为何仍不代表完整原生 Promise？

关卡四：写清教学实现的边界

对照 ECMAScript 规范，至少记录下面五类差异：

  • 原生 Promise 使用内部 slots，不暴露可修改的 state / result。
  • 原生 then 涉及 constructor species 与 Promise capability。
  • host 负责 Promise jobs 与未处理 rejection 跟踪。
  • 静态组合方法、finally、迭代器关闭等不属于 A+ 核心。
  • 生产实现还涉及性能、内存、调试栈、跨 realm 与宿主集成。
不要直接把教学实现用于生产

它的价值是暴露机制与边界条件，不是替代引擎内置 Promise 或成熟 polyfill。

提高项：通过验收后再选

finally

验证不改变原 value / reason，并等待 cleanup thenable；不要简单写成两个相同 handler。

all

保持输入顺序、处理空 iterable、快速 rejection、thenable 吸收。

race

第一次 settled 获胜；空 iterable 保持 pending。

allSettled

等待全部完成，保留每项状态与对应 value / reason。
