P01 · Chaining

每次 then 都创建一条新因果链

父 Promise 只决定选哪个 handler；handler 的返回或异常决定新的 child Promise。理解这一层，错误恢复和链式组合就不再神秘。

40–55 分钟 难度：中等 产出：传播矩阵测试

不要把父状态复制给 child

parent 结果

选择并执行 handler
→
决定 child

如果父 Promise rejected，但 onRejected 成功返回一个普通值，child 应该 fulfilled。这就是 catch 能恢复链条的根本原因。

本课仍有一个受控缺口

先处理普通返回值、抛错和缺失 handler。若 handler 返回 thenable，暂时让对应测试保持 todo；第五课会实现完整解析程序。

1

为五行矩阵各写一个最小链

每个测试都保存 const child = parent.then(...)，先断言 child 与 parent 不是同一对象，再观察 child 的最终结果。

交付：五个传播测试，加一个“每次 then 返回不同 child”的身份测试。

reaction 需要携带 child 的能力

上一课的 reaction 只有两个 handler。现在需要再携带 child 的 resolve / reject 能力：

调用 parent.then(onFulfilled, onRejected)
  创建一个新的 child Promise 及其 resolve / reject 能力
  创建 reaction：两个 handler + child capability
  将 reaction 注册到 parent
  立即把 child 返回给调用者

未来处理 reaction
  根据 parent 状态选择 handler
  用 handler 的结果或异常决定 child

then 返回 child 的动作是同步的；child 何时 settled 取决于 reaction job。不要等 handler 执行后才返回 child。

2

先完成 child 创建与身份测试

  1. 连续调用两次 parent.then。
  2. 证明两个返回值都不是 parent，且彼此也不相同。
  3. 证明在 scheduler flush 前，两个 child 都未被 handler 结果结算。

交付：一张 parent → reactions → children 的对象关系图。

把传播集中在一个 reaction runner

以下伪代码用于检查分支完整性：

runReaction(parentState, parentResult, reaction)
  选择与 parentState 对应的 handler

  如果 handler 不是函数
    fulfilled 分支：把 parentResult 传给 child 的 resolve
    rejected 分支：把 parentResult 传给 child 的 reject
    结束

  尝试以 parentResult 调用 handler
    得到 x：把 x 交给 child 的 resolve（第五课增强）
  如果 handler 抛出 e
    以 e reject child
两个容易混淆的方向

失败 handler 返回值意味着恢复，所以走 child resolve；成功 handler 抛出异常意味着新失败，所以走 child reject。

3

让传播矩阵逐行变绿

  1. 先实现普通成功返回。
  2. 再实现失败 handler 的恢复。
  3. 加入 handler 抛错。
  4. 最后处理两个缺失 handler 的透明传播。

交付：完整传播矩阵、一次失败 handler 恢复的时间线，以及仍为 todo 的 thenable 测试。

逐级提示

提示 1：then 返回了 parent 本身

创建 child 的职责属于每次 then 调用，而不是 parent 构造阶段。每条 reaction 必须绑定自己的 child capability。

提示 2：onRejected 返回值后 child 仍 rejected

不要按“父状态”直接复制 child 状态。只要 handler 正常返回，返回值就进入 child 的 resolve 路径。

提示 3：缺失 handler 导致 TypeError

先检查可调用性，再决定是否执行。非函数 handler 应被忽略，并按父状态透明传递 value 或 reason。

从内存补全三条链

不要运行，写出每个 child 的最终状态与结果：

// A: 成功转换
childA = fulfilled(2).then(x => x * 3)

// B: 错误恢复
childB = rejected("bad").then(undefined, reason => reason.length)

// C: 新错误
childC = fulfilled("ok").then(() => { throw "boom" })
核对答案

A 是 fulfilled(6)；B 是 fulfilled(3)；C 是 rejected("boom")。规范允许任意 JavaScript 值作为 rejection reason。
