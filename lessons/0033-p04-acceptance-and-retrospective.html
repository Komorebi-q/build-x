1

整理可重复运行的证据

  1. 记录 Node、包管理器、测试框架和目标 parser 版本。
  2. 给出干净环境安装、测试和编译示例的精确命令。
  3. 保存测试矩阵与摘要，不只给绿色截图。
  4. 保存一个成功输入的 source→tokens→两棵 AST→code 轨迹。
  5. 保存一个跨行失败输入的结构化诊断和人类可读渲染。

交付：命令、环境、矩阵、成功轨迹与失败诊断。

关卡三：十分钟闭卷讲解

  1. 写出核心文法，并解释 tokenizer 为什么不建立嵌套关系。
  2. 手演一次跨行输入的位置游标。
  3. 手演嵌套 call 的 parseExpression 调用与 token 消费。
  4. 画 enter/exit 轨迹，解释 parent 和 child order。
  5. 比较源 Call 与目标 Call schema，并说明顶层 wrapper。
  6. 解释 generator 的分号、逗号、引号责任。
  7. 展示两个不同 phase 的诊断为何具有相同外形、不同 code。

关卡五：模型边界声明

  • 核心语法只支持哪些数字、字符串、名字、调用与空白；
  • 是否允许跨行字符串、转义、空输入与多个顶层表达式；
  • 位置采用何种 line/column/index 与 end 约定；
  • 错误是 fail-fast 还是恢复；核心实现不应误称支持多错误恢复；
  • 目标 AST 与 ESTree/Babel AST 的相似和不兼容之处；
  • 为什么 location 不等于 source map；
  • 不包含作用域、符号表、类型检查、优化、模块、完整 JavaScript 解析和生产级安全性。
