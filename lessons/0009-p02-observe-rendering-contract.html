P02 · Renderer Contract

先观察 React 做了什么，再设计自己的渲染器

这一课不写渲染器。你会把“组件变成界面”拆成输入、计算与 DOM 副作用，并通过实验建立后续实现必须守住的行为契约。

45–60 分钟 难度：入门诊断 产出：行为记录与 render / commit 图

完成后你应该能够

区分三种对象element 描述、Fiber 工作节点、真实 DOM 节点。
区分两个阶段render 计算“应该变成什么”，commit 才改变宿主环境。
说明为什么要分阶段计算可以切片，半成品 DOM 不应暴露给用户。
设计可观察证据用日志、DOM 快照与副作用计数证明行为。

实验一：一次更新里发生了什么

准备一个只含计数器和嵌套文本的极小 React 页面。不要阅读框架源码，先在组件体、事件处理器和 DOM 观察点记录顺序。点击一次后回答：

  1. 事件处理器何时结束？组件函数何时再次执行？
  2. 组件函数执行时，页面上的旧 DOM 是否仍可见？
  3. 一次状态更新是否必然意味着替换整个容器？用节点身份证明。
  4. 连续安排两次基于旧值的更新，与两次函数式更新，结果是否相同？先预测再运行。
1

写一份时间线，而不是只记最终数字

至少记录“事件开始 → 安排更新 → 事件结束 → 组件计算 → DOM 变化”五个观察点。每个观察点注明你看到了什么证据。

交付：一张预测 / 实际 / 解释三列表和一条更新顺序时间线。

这只是课程的教学模型。真实 React 有更多优先级、缓存、恢复与宿主配置机制；本项目只抽出足以解释核心数据流的最小骨架。

不要把 Virtual DOM 当作真实 DOM 的复制品

element 是“我想要什么”的普通描述；Fiber 是“这次更新工作做到哪里”的可变记录；DOM 是浏览器持有的宿主对象。三者生命周期不同。

前置诊断

闭卷回答。不会的项目不是失败，而是决定后续提示需要多具体。

  1. DOM property 与 HTML attribute 有什么可能的区别？举一个你愿意实验验证的例子。
  2. 深度优先遍历一棵树时，如何只用 child、sibling、parent 找到下一个节点？
  3. JSX 最终必须变成浏览器能执行的什么形式？
  4. 为什么“组件函数被调用”不等于“DOM 已经更新”？
  5. 若工作在中途暂停，哪些数据可以留在内存，哪些副作用不能提前发生？
第 2 题提示 1

有 child 时优先向下；没有 child 时，尝试 sibling；仍没有时向上寻找某个祖先的 sibling。

第 5 题提示 1

比较“普通 JavaScript 对象尚未完成”和“用户已经看到一半 DOM 更新”两种中断结果。
