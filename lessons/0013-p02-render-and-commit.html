P02 · Render / Commit

候选树完成之前，不触碰可见页面

render 阶段可以被切片，因为它只构建内存中的候选树；commit 阶段集中应用 DOM 副作用，让用户不会看见一半新、一半旧的界面。

60–90 分钟难度：中等产出：提交边界与原子可见性测试

两个阶段解决两类问题

阶段主要工作能否暂停可观察副作用
render / reconciliation执行组件、建立候选 Fiber、标记未来变更教学模型中可以不应修改已挂载 DOM
commit按标记执行插入、更新、删除本项目视作连续完成DOM 在此阶段改变

“render”在这里不是“画到屏幕上”，而是计算。命名容易误导，所以每次调试都问：我正在构建候选树，还是正在改变宿主环境？

区分三种根引用

current root

与当前 DOM 对应、已经提交的 Fiber 树。

work-in-progress root

本轮正在构建的候选树，失败或未完成时不可见。

next unit

本轮 render 的恢复点；为空不自动代表已提交。

container root

连接浏览器 DOM 容器的教学 Fiber 根。

1

画一次被切成三轮的首次挂载

每轮标出 next unit、候选树已完成部分、容器 DOM 内容。只有第三轮 render 完整结束后，才画出一次 commit。

交付：三轮 render + 一次 commit 的状态快照图。

提交遍历只消费已经准备好的工作

首次挂载时，可以先把每个宿主 Fiber 的 DOM 节点在 render 阶段创建好，但暂不连接到可见容器。commit 遍历再把它们接到正确父 DOM 下。

  1. 从 work-in-progress root 的 child 开始，不把教学 root 当真实 DOM child 插入。
  2. 找到当前 Fiber 对应的宿主 parent DOM。
  3. 应用当前 Fiber 的 effect；首次挂载先只有 placement。
  4. 继续遍历 child 与 sibling，直到整棵候选树完成。
  5. 提交后把候选 root 提升为 current root，并清理临时引用。
2

用 DOM 操作记录器验证 commit

让宿主边界记录 create、append、property set。断言 render 轮次可以发生 create，但 container append 必须等到 commit；同一棵树只提交一次。

交付：操作日志断言与一次真实 DOM 集成验证。

设计一个“中途暂停不泄漏”的负向测试

给一棵需要多轮处理的树，只运行第一轮后检查容器。它应保持旧内容或为空；继续完成并 commit 后，完整新结构一次出现。

常见失败信号

若暂停后容器出现部分节点，说明 DOM append 仍藏在 render 工作单元内。先移动副作用边界，不要用隐藏元素掩盖。

逐级提示

提示 1：为什么出现重复节点

检查一次 commit 后是否清空 work-in-progress root，调度器是否在 nextUnit 为空时反复触发 commit。

提示 2：root 应该保存什么 DOM

教学 root 不代表页面标签，它的 dom 可以指向外部 container，children 才是待插入的 UI。

提示 3：create DOM 算不算可见副作用

离线创建尚未连接的节点通常不会改变页面；真正需要守住的是对已挂载宿主树的变更边界。
