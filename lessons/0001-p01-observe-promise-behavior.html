P01 · 行为基线

先观察，再实现 Promise

这一课不写 Promise。你先用原生 Promise 建立可验证的行为模型：executor 何时运行、状态如何锁定、handler 为什么稍后执行。

25–40 分钟 前置诊断 产出：状态图 + 顺序解释

完成后你应该能够

区分两个时刻

executor 同步执行；reaction handler 不在当前调用栈执行。

画出三态模型

pending 只能单向转为 fulfilled 或 rejected。

用证据回答

先预测输出，再运行实验校正，而不是凭印象背结论。

确认学习起点

根据解释质量决定直接前进还是先补调用栈与队列。

与整条路线的关系

P01 是后续 React 调度、Node 事件循环和服务器并发模型的热身。这里训练的核心不是 API，而是“状态 + 队列 + 传播 + 证据”。

实验一：分开 executor 与 handler

不要先运行。把你预测的五行输出写下来，并为每一行标注它来自“当前调用栈”还是“稍后排队的 reaction”。

console.log("A");

const p = new Promise((resolve) => {
  console.log("B");
  resolve("D");
  console.log("C");
});

p.then((value) => console.log(value));
console.log("E");
1

执行预测—观察—解释循环

  1. 闭卷写出输出顺序。
  2. 在浏览器控制台或 Node 中运行三次。
  3. 若结果与预测不同，只修改解释，不要只抄正确顺序。
  4. 用一句话解释：为什么调用 resolve 后仍先出现 C 和 E？

交付：五行输出、每行所属阶段，以及一段不超过 80 字的因果解释。

核对结果（完成预测后再展开）

顺序应为 A → B → C → E → D。构造器立即调用 executor，所以 B 属于当前调用栈；resolve 锁定结果，但 then 的 handler 作为 reaction job 稍后执行。

实验二：第一次结算获胜

再次先预测。注意：这段实验验证的是“一次性决定”，不是微任务先后。

const events = [];

const p = new Promise((resolve, reject) => {
  resolve("first");
  reject("second");
  resolve("third");
});

p.then(
  (value) => events.push(`fulfilled:${value}`),
  (reason) => events.push(`rejected:${reason}`)
);

queueMicrotask(() => console.log(events));
2

把行为改写成不变量

  1. 预测数组最终只有哪个元素。
  2. 分别交换三次调用的顺序，再预测一次。
  3. 把观察总结成一条测试可断言的不变量。

交付：一句形如“当……时，无论之后……，都……”的不变量。

核对结果

最终只有 fulfilled:first。第一次有效的 resolve / reject 锁定结果，后续调用不改变状态和值。注意“值不变”指身份不变，不表示对象会被深度冻结。

把实验压缩成状态机

PENDING可迁移
→
FULFILLEDvalue 固定
或
REJECTEDreason 固定

状态机回答“现在是什么”；reaction 队列回答“状态确定时需要通知谁”。这两个问题先分开，后面再连接。

3

闭卷重画

  1. 合上本页，用纸画出三个状态和合法箭头。
  2. 在终态旁写出必须保存的数据。
  3. 再补一条禁止箭头，并解释为什么必须禁止。

交付：一张自己的状态图；不要截图本页。

先不要混用三个词

fulfilled、settled 与 resolved 不完全相同。尤其是 resolve 到另一个 pending thenable 时，当前 Promise 已被锁定，却可能仍未 fulfilled。第五课会专门处理。

前置诊断

不查资料，用自己的话回答：

  1. 为什么 executor 可以同步执行，但 then handler 不应同步执行？
  2. 调用 resolve 与调用 handler 是同一个动作吗？
  3. 如果同一 Promise 注册三个 then，状态机需要变成三个吗？为什么？
  4. 你会用什么证据证明 handler 没有在当前栈执行？
自评分标准
  • 可以前进：能区分“决定结果”和“通知观察者”，并能设计输出顺序测试。
  • 先补 20 分钟：只能背出“Promise 是异步的”，但解释不了 executor 为何立即运行。
  • 请求讲解：调用栈、队列或回调注册仍模糊。把你的预测和困惑发给 AI，让它只解释概念，不写实现。
