提高项一：模块缓存不是性能小技巧

缓存改变模块的执行身份：同一 module id 多次被请求时，应返回同一个模块实例，而不是重新运行 wrapper。若还要面对循环，仅用“执行完再写缓存”不够。

缓存状态发生什么再次请求同 id
absent创建 module 实例先把实例登记为 loading
loadingwrapper 尚未返回，可能位于循环中返回当前部分初始化的 exports，或按声明策略报错
loadedwrapper 已完成直接返回同一 module.exports
failed（可选）wrapper 抛错明确删除、保留或重抛策略
这仍然更接近 CommonJS wrapper 语义

“在执行前缓存 module 对象”可以阻止简单循环无限递归，却不会自动得到原生 ESM 的实例化阶段、TDZ、导出解析和 live bindings。不要把通过一个循环夹具写成“支持完整 ESM 循环”。

缓存设计提示 1

缓存键必须是稳定 module id/identity，不能是原始 specifier；同一个 ./x.js 在不同父模块下可能不同。

缓存设计提示 2

在调用 wrapper 之前登记实例，循环回到同 id 时才有可返回的部分对象。

缓存设计提示 3

用菱形副作用测试证明 wrapper 从两次变一次，同时断言两个 importer 获得同一导出对象身份。
